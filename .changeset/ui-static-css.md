'@meonode/ui': minor
---

Experimental: the runtime side of `@meonode/compiler`'s `experimental_extractCss` option. A call site the compiler named at build time renders with the class and rule it would have had uncompiled. The runtime skips that node's style work at render: no theme resolution, serialization or hashing. A node built from a template joins its values into the registered text and names the result, hashing once per distinct set of values. Compiled modules register their styles with `registerStaticCss` and `registerStaticTemplate`, write template values with `toCssValue`, and call factories imported from other modules through `__meoFactoryCall`. All four are exported from every entry, and `__meoFactoryCall` also from the new `@meonode/ui/factory-call`, which imports nothing, so a module that only calls an imported factory, such as a route handler, loads no React or Emotion for it. That entry joins a call once the join is loaded, which the first call through `@meonode/ui` does; an app built without the compiler loads no join at all. Everything that renders a registered style, the join among it, loads only once compiled output registers a style or calls through `@meonode/ui`. An app built without the compiler ships 1.3 KB gzip more than 3.3: the checks for compiled marks on the paths every node takes (the walk, `StyledRenderer`, the compiler's prop keys), the record of each factory with its initial-props fingerprint, and the run plumbing runtime nodes share with named ones.

- **Same output.** Each named style goes through Emotion's own cache under Emotion's name, at the point in render order where Emotion would insert it. Class names, rule order, server HTML and hydration are the same with extraction on and off. The cache's stylis plugins apply as before, and `StyleRegistry`, a scoped server render without a cache provider and React Server Components all work unchanged.
- **Same element types.** A named node with no rule before it since its walk's start, a component, a boundary or a memoized node renders through MeoNode's styled renderer, which inserts the run of named styles that begins at it; any other named node renders a plain element, and its style goes in with the rule before it. A node the compiler marks as a carrier renders through the styled renderer on every render, and on a render where a rule comes before it its style goes in with that rule's run. The compiler marks every node whose place may change between renders, so a node's element type is the same on every render and a named node never remounts, or loses its state, where the same node uncompiled would not. If a compiled node arrives without the carrier it needs, the runtime renders it as one, so the output stays the same; such a node may remount when its position changes.
- **Factories from other modules.** The compiler can't see a `createNode` factory's initial props across modules, so it hands a call of an imported factory whose own style is static to `__meoFactoryCall`. At the call's first render the runtime joins the call's style with the factory's initial props, as the factory merges them, names the result once, and renders the call as a named node from then on. A theme token in a condition or a selector of the joined style resolves per theme, where the node renders. A callee that `createNode` did not make, and a style that could differ between renders (a function, a `theme` or `disableEmotion` prop, or theme-token keys whose literal text could meet another key's), are called as written.
- **Boundaries keep their order.** A named style is never inserted ahead of a component, a memoized node, `Suspense`, `SuspenseList` or `Activity` on behalf of a node inside it. Each of these may render its children later or elsewhere.

Output without the compiler's markers renders exactly as before.
