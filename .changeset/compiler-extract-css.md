An experimental `experimental_extractCss` option names the styles of host and layout factory call sites at build time. For a call site whose whole style is known when the module is built, the compiler writes the serialized styles and class name the runtime would compute for it, and the runtime inserts them through Emotion under that name, so the node renders with the class and rule it would have uncompiled. A value only the call site knows, but provably a string or a number (a template literal or arithmetic over plain reads), becomes a hole in a template the module registers; the runtime joins the template with the call site's values and names the result. A node with any other value only known at runtime stays on the runtime path. Host call sites whose children may render a component also carry `__meo$p`, the positions before which the runtime keeps a slot for the static styles that began earlier. It needs a `@meonode/ui` that reads `__meo$n`, `__meo$t`, `__meo$i` and `__meo$p` and exports `registerStaticCss`, `registerStaticTemplate` and `toCssValue`. Off by default, and the output is then unchanged.
